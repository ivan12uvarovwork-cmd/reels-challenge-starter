# Раскладки и графика. Один устойчивый язык, не витрина вариантов

Код: `src/style.ts` (единственный объект `STYLE`, никакого переключения
пресетов). Идея: зритель должен узнавать ролик с первого кадра, а не
гадать, какой сегодня стиль — один язык на весь канал устойчивее, чем
набор переключаемых вариантов.

Если тебе для старта, наоборот, нужен выбор из готовых пресетов —
смотри `ПРЕСЕТЫ_стилей.md`: пять вариантов палитры и композиции (жёлтый,
токсичный лайм, минимал, liquid glass, журнал), более ранний, но рабочий
подход. То, что ниже — более поздняя и более устойчивая версия: возьми
из неё b-roll-раскладки и графику как есть, а `bg`/`ink`/`capBg`/`capInk`
из `style.ts` смени на цвета своего бренда.

Стиль держится не на палитре, а на двух вещах:

## 1. Три раскладки b-roll

В кадре в любой момент — одна из трёх:

1. **Сплит-экран.** Кадр делится по горизонтали: сверху b-roll-вставка, снизу видео с говорящим. Оба видны одновременно. Верхняя карточка со скруглёнными **нижними** углами (не прямая линия раздела) — под ней всегда играет базовый полноэкранный аватар, поэтому в скруглении естественно проглядывает его фон. Убирать базовый видео-слой из композиции нельзя — тогда в углах будет чёрное вместо фона. **Пропорция не обязана быть 50/50** — `splitRatio` (0-1, доля высоты под b-roll) подбирается по факту конкретного файла: высокий портретный скрин читается лучше с большей долей (0.6-0.65), маленькая иконка — можно сузить (0.35-0.4), оставив больше места говорящему. Планируется на Фазе 3, не жёстко пополам.
2. **Полный экран.** B-roll занимает весь кадр целиком, говорящий пропадает из кадра совсем — остаётся вставка и субтитр внизу. Голос продолжает звучать (звук не переключается на b-roll). Подложка под вставкой — чёрный фон с едва заметной белой сеткой и лёгким синим градиентом снизу (`ScreenBacking` внутри `FullBleedBRoll`), а не голый чёрный — видна там, где `contain` оставляет поля вокруг landscape-скриншота. **Если вставка сама вертикальная** (портретный скрин/видео, пропорции близки к 9:16) — `fit="cover"` вместо `contain`, тогда она займёт весь кадр без полей (и подложка не будет видна вообще, это нормально).
3. **Кружок.** Говорящий уходит в маленький круглый PIP слева, b-roll занимает всё остальное пространство фоном.

### Значок вместо полной раскладки

Не для каждого упоминания сервиса/бренда нужна полная раскладка (Split/Full/Pip) — если задача просто «назвать/подписать», не показывать демо, используй **`BadgeStage`/`LogoBadge`**: белая скруглённая плашка поверх обычного полноэкранного аватара (или поверх любой другой раскладки) — иконка + опционально текст с названием рядом. Не переключает раскладку, не занимает половину экрана, тот же приём входа/выхода (window0), что и у `BRollStage`. Код — там же, `ui/BRollLayouts.tsx`.

Крупно и по центру, не мелко в углу — мелкое теряется в кадре. Иконка 96px, текст 48px, по умолчанию — над головой говорящего (верх STAGE). Это ориентир, не гарантия для любой съёмки — на конкретном исходнике, где сверху мало места, подвинь и проверь рендером кадра (Фаза 5 skill'а `video-montage`), не сдвигай координаты вслепую.

### Полный экран со вставкой — карточка, не край-в-край

`FullBleedBRoll` вставляет картинку/видео не на всю ширину — отступ слева/справа (56px), скруглённые углы (28px), это карточка на подложке, а не край-в-край. Подложка (`ScreenBacking`, чёрный + едва заметная белая сетка + синий градиент снизу) — **не статика**: градиент дышит волной по прозрачности синего свечения (0.20–0.55, не только позиция стопа), период 2.2с — так заметно даже в коротком 2-3-секундном сегменте (слишком слабая амплитуда по одной только позиции стопа на глаз не читается). Вычисляется по кадру и подставляется в тот же `background-image` компонента — не отдельным слоем поверх (см. предупреждение о баге ниже).

⚠️ Подложка и картинка — CSS-свойства/дети ОДНОГО `AbsoluteFill`, не два соседних непрозрачных полноэкранных слоя подряд: это приводит к тому, что `<Img>` вообще не отрисовывается (Chrome headless путается в компоновке двух непрозрачных full-screen слоёв подряд, когда второй — асинхронно загружаемая картинка). Инсет-картинка реализована как вложенный `<div>` внутри той же `AbsoluteFill`, не сиблинг — так безопасно, проверено рендером кадра. Подробности — `ГРАБЛИ.md`, п.14.

### Значок-акцент под слово (IconCue)

Не логотип продукта, не файл-картинка — акцент под конкретное CTA-слово в речи: «сохрани», «лайк», «поделись» и подобное. `IconCueStage`/`IconCueName` из `ui/IconCue.tsx`, инлайн SVG (не PNG — остаётся чёрно-белым без нового ассета в проекте). Появляется с отскоком (scale 0.6→1.15→1.0 за ~0.3с), не просто фейдом — короткий акцент так заметнее на фоне сдержанных переходов остальной графики. Набор иконок — общий словарь в файле, пополняется по мере надобности (сейчас только `bookmark` — общепринятая форма значка «сохранить», не логотип). **Позиция — прямо над субтитрами** (`CAPTION_BOTTOM`) — значок логически при том же слове, что и подпись, глазу естественнее держать их рядом. С хуком не сталкивается — их окна по времени обычно не пересекаются (хук — самое начало, CTA-значки — где угодно дальше).

```tsx
import { IconCueStage, type IconCueSegment } from "./ui/IconCue";

const ICON_CUES: readonly IconCueSegment[] = [
  { from: 38.92, to: 40.32, icon: "bookmark" }, // "Сохрани себе это видео —"
];

<IconCueStage segments={ICON_CUES} />
```

### AI-сгенерированный b-roll

Когда нужен абстрактный/атмосферный видеоряд без конкретного продукта и подходящего файла в проекте нет — модели вроде `kling-2.6/text-to-video` (доступна через агрегаторы вроде kie.ai) генерируют клип нативно 9:16 (`fit="cover"` на весь экран, без полей). Это платная генерация — согласовывай с собой/заказчиком перед запуском, не по умолчанию. Полная механика вызова API — `Rules/skills/video-montage/SKILL.md`, раздел «AI-генерация b-roll».

Между любыми двумя раскладками — и между раскладкой и обычным полноэкранным видео — обязательна анимация перехода (масштаб плюс прозрачность). Жёсткий рез запрещён. Раскладка меняется по смыслу ролика — когда меняется то, что зритель должен разглядывать, а не по расписанию.

Код: `src/ui/BRollLayouts.tsx` — `SplitBRoll`, `FullBleedBRoll`, `PipBRoll`, и `BRollStage`, который переключает их по таймлайну сегментов с анимацией входа/выхода (переиспользует `cue`/`window0` из `ui/motion.ts` — не пиши анимацию заново на каждый проект).

```tsx
import { BRollStage, BadgeStage, type BRollSegment, type BadgeSegment } from "./ui/BRollLayouts";

const segments: readonly BRollSegment[] = [
  { from: 11.2, to: 18.3, variant: "full", broll: { kind: "image", src: "media/screenshot-one.png" } },
  { from: 20.6, to: 27.3, variant: "split", broll: { kind: "video", src: "media/demo-two.mp4" }, avatar: { kind: "video", src: "media/avatar-video.mp4" }, splitRatio: 0.6 },
  { from: 30.0, to: 34.0, variant: "full", broll: { kind: "image", src: "media/mobile-screen.png" }, fit: "cover" }, // вертикальный скрин - на весь кадр
];

const badges: readonly BadgeSegment[] = [
  { from: 5.0, to: 9.2, icon: { kind: "image", src: "media/logos/tool-logo.png" }, label: "Tool Name" },
];

<BRollStage segments={segments} />
<BadgeStage segments={badges} />
```

Сегменты не обязаны примыкать впритык — оставь между ними 0.15–0.25с зазора или лёгкий нахлёст, тогда вход одной раскладки и выход другой пересекутся по времени, и получится кросс-фейд, а не «пропала-появилась» с чёрным кадром между.

### Монтаж внутри b-roll

`BRollMedia` — это не просто ссылка на файл, а мини-монтаж внутри вставки: какой момент источника показывать, нужно ли ускорить/замедлить, и нужен ли пунш-ин на конкретную деталь. Все три поля опциональны и работают только для видео (кроме `zoom`, который годится и для картинки):

```tsx
const broll: BRollMedia = {
  kind: "video",
  src: "media/demo-two.mp4",
  trimStartSec: 6.2,     // показываем не с начала файла, а с момента клика
  trimEndSec: 11.4,
  speed: 0.6,             // замедлили сам клик - ему нужен вес
  zoom: [{ from: 20.6, to: 23.0, direction: "in", focus: "62% 28%" }], // пунш-ин на счётчик в углу экрана
};
```

`trimStartSec`/`trimEndSec` уходят в `trimBefore`/`trimAfter` у `OffthreadVideo` (секунды переводятся в кадры через `sec()`) — какая часть исходного файла играет, а не когда вставка появляется в композиции (это по-прежнему `from`/`to` самого `BRollSegment`). `speed` — это `playbackRate`; звук вставки всегда `muted`, поэтому питч не в счёт. `zoom` — отдельный хук `useBRollZoom` (не путать с `useAvatarZoom`): якорь — не лицо, а `focus`, точка внутри самой вставки, снятая с реального превью-кадра. Все три поля планируются на Фазе 3 skill'а `video-montage`, раздел «Монтаж внутри b-roll» — не подставляются в коде на глаз.

Когда тема достаточно ёмкая для нескольких разных кадров (пара экранов одного продукта, а не один статичный скриншот) — не тяни один `BRollSegment` на весь интервал темы, а поставь подряд 2-4 коротких (`0.6-1.0s` каждый — единственное исключение из общего минимума `1.5s` на вставку), с разными `broll` (разные `trimStartSec`/`trimEndSec` того же файла или разные файлы). Отдельного «жёсткого реза» механизм не поддерживает — между ними всё тот же мягкий вход `BRollStage`, никакого нового компонента писать не нужно.

### Zoom на чистых кадрах аватара

Там, где b-roll нет и в кадре только говорящий (интро, аутро, любая растянутая пауза без вставки) — не оставляй масштаб статичным. Лёгкий Ken Burns (`useAvatarZoom` из `ui/zoom.ts`) на 5+ секунд чистого аватара делает разницу между «монтажной паузой» и «зависанием кадра».

```tsx
import { useAvatarZoom, type ZoomSegment } from "./ui/zoom";

const ZOOMS: readonly ZoomSegment[] = [
  { from: 0, to: 10.06, direction: "in" },   // интро - подводит к хуку
  { from: 36.5, to: 42.68, direction: "out" }, // аутро - открывает кадр к CTA
];

const scale = useAvatarZoom(ZOOMS);
<OffthreadVideo src={...} style={{ ..., transform: `scale(${scale})` }} />
```

Направление — по смыслу момента: `"in"` подтягивает внимание (хук, важная мысль), `"out"` отпускает (финал, переход к CTA). Планируется на Фазе 3 skill'а `video-montage` вместе с b-roll — не отдельным шагом.

## 1.5. Хук-заголовок в первые секунды

Первые секунды решают, долистает зритель дальше или нет — не жди, пока хук проговорят вслух целиком, выведи его крупным текстом сразу. `HookTitle` из `ui/Hook.tsx`, окно по умолчанию первые 4с ролика, анимированный вход/выход (прозрачность+сдвиг, тот же `cue` из `ui/motion.ts`).

**Два яруса, не одна строка**: крупный ярус `big` — число или ключевое слово (1-3 слова), помельче `small` под ним — остаток мысли. Текст прямо на видео, без чёрной плашки — держится тенью (`text-shadow`), не коробкой. Если в хуке есть число — оно и есть `big`.

**Пока хук на экране — `Subtitles` молчат** (`suppressUntil` = время окончания хука): два текстовых блока одновременно перегружают первый экран, хук уже несёт ту же реплику.

**Шрифт — можно не тот, что у субтитров.** Единственное официальное исключение из правила «один шрифт на весь стиль»: для заголовка можно взять `Montserrat` или `Days One` (оба добавлены в `fonts.tsx`, кириллица проверена реальным рендером, не только по cmap). Дефолт — `Montserrat`. Остальной текст (субтитры, значки) — по-прежнему только основной шрифт.

**Позиция — низ кадра, на месте субтитров** (`CAPTION_BOTTOM`) — субтитры на это время всё равно молчат, а в шортсах взгляд привычно смотрит вниз.

```tsx
import { HookTitle } from "./ui/Hook";
import { Subtitles } from "./Subtitles";

<HookTitle big="3" small="инструмента, которые экономят часы каждую неделю" to={4} />
<Subtitles captions={CAPTIONS} suppressUntil={4} />
```

## 2. Субтитры группами по 1-2 слова

Каждая запись `Caption` — это уже 1-2 слова, не целая фраза. Пришло время `from` — группа появляется быстрым фейдом целиком, пришло `to` — сменяется следующей. Никакого проявления по буквам внутри группы (печатная машинка выглядит эффектно, но синхронизация с речью важнее самого эффекта).

Чёрная плашка, скруглённые углы (не капсула во всю ширину строки), белый текст. Код: `src/Subtitles.tsx`.

**Тайминги — только из честной пословной ASR-транскрибации, не из оценки.** Границы субтитров по паузам в аудио (`ffmpeg silencedetect`) плюс пропорциональное деление по числу символов внутри фразы на реальном материале расходятся с настоящей речью на **до 2 секунд** (см. `ГРАБЛИ.md`, п.11). Используй `faster-whisper` с `word_timestamps=True` (модель `small`, `language="ru"`, работает локально на CPU, ставится через `pip3 install faster-whisper`): даёт честный `start`/`end` на каждое слово. Группируй по 1-2 слова, **не объединяя слова через реальную паузу ≥0.3с** — иначе на экране одновременно виден хвост одного предложения и начало следующего.

ASR путает бренды и заимствования (в тесте: Google→«Бугл», Stitch→«стичь», Canva→«конвас», Pinterest→«пинтерест», коллаж→«калаш») — тайминги из распознавания верные, слова сверяй и правь по уже одобренному в Фазе 2 skill'а тексту сценария, не доверяй ASR-орфографии вслепую.

## Шрифт

Один официальный Google Font, вес 700 — уже лежит в `public/fonts/` как `.woff2`, ничего докачивать не нужно. Проверяй любой новый шрифт не только по `cmap` (наличие кодпоинтов), но и реальным рендером строки — некоторые шрифты технически «поддерживают» кириллицу, но рисуют её через похожие латинские буквы (Т/т → форма "m" и т.п.), и это не видно, пока не отрендеришь и не посмотришь глазами. Подробности и как это ловится — `ГРАБЛИ.md`, п.8.

## Цвет

Строго чёрно-белый в этом ките: фон и плашка субтитров — чёрный, текст — белый. Третьего цвета нет намеренно — минимум, который проще всего перенести под свой бренд: смени `bg`/`ink`/`capBg`/`capInk` в `style.ts` на цвета из своей палитры, вся логика выше (раскладки, хук, субтитры) продолжит работать без изменений.

## Безопасные зоны

Сверху 210px, снизу 470px, колонка текста 760px. Заданы в `src/config.ts` (`SAFE`), b-roll живёт в полосе `STAGE` между верхней зоной и субтитрами. Не подставляй числа руками в компонентах.

## Запрещено

- Жёсткий рез между раскладками b-roll без анимации перехода.
- Субтитр длиннее 1-2 слов на одну запись, или тайминги "на глаз"/по оценке вместо честной пословной ASR-транскрибации.
- Группа слов, перескакивающая через реальную паузу в речи ≥0.3с.
